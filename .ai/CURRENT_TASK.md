# Текущая задача: нативное открытие Wallet в Telegram

Обновлено: 2026-11-01. Статус: в работе.

## Цель и границы

Исправить повторный уход во внешние ссылки/предложение скачать Telegram после выбора Walt. В Telegram формировать TON Connect запрос официальным connector SDK и передавать готовую ссылку непосредственно в WebApp.openTelegramLink. Сохранить браузерный выбор, адрес, восстановление и отключение.

## План и критерии готовности

1. Проверить официальный API connect и причины внешнего redirect в UI SDK.
2. Получать Walt из списка SDK, формировать ссылку через connector.connect и открывать её нативным Telegram API без внешнего fallback.
3. Обработать ошибку и повтор подключения, не создавать фиктивный адрес.
4. Выполнить lint/build/diff-check и временную проверку маршрута с mock API; отметить отсутствие реального устройства.

## Результат и проверки

Добавлен `src/lib/connectTelegramWallet.ts`: Walt получается из официального списка SDK, `connector.connect` синхронно формирует полный TON Connect t.me URL и начинает ожидание ответа. Готовая ссылка передаётся непосредственно в `WebApp.openTelegramLink`, минуя redirect-эвристики UI SDK. При отсутствии поддерживаемого Telegram API или небезопасной ссылке показывается ошибка без внешнего fallback.

`WalletConnect` распознаёт Telegram по initData либо известной platform, отменяет незавершённую попытку перед повтором/при размонтировании; успешная сессия не отменяется. busy снимается после отправки запроса, не после подтверждения кошельком. Общий браузерный выбор, адрес и отключение сохранены.

Проверки: lint/build/diff-check PASS. Прежние 2 предупреждения Date.now и bundle >500kB. Временный in-memory harness на реальном компоненте/helper с mock React/SDK/Telegram подтвердил: точная SDK-ссылка передаётся нативному API, выбран Walt, известная platform без initData работает, retry abort старой попытки, отказ не создаёт адрес, ошибка нативного API не ведёт во внешнее окно, подтверждённый адрес отображается, браузерный сценарий остаётся модалкой. Harness не оставил файлов/зависимостей. Реальный Telegram и подтверждение в Walt не проверены; публикацию выполняет основной агент.

Проверки нативного маршрута: lint/build/diff-check PASS, reviewer PASS. Временный harness на компоненте/helper проверил передачу точной SDK-ссылки в openTelegramLink, отсутствие window.open fallback, повтор/abort, отказ без фиктивного адреса, подтверждённый адрес и браузерный выбор. Реальное устройство не проверено. Публикация выполняется в рамках ранее запрошенного обновления сервера.
